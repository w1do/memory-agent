# ignore-policy

Исключения при сканировании проекта. Отдельное изменение (A1), выпускается после V1.

## Требования

### Требование: соответствие Git

Учёт `.gitignore` SHALL соответствовать правилам Git: вложенные `.gitignore`, отрицания (`!`), привязка шаблонов к каталогу или корню.

Сценарий: вложенный .gitignore
- Given файл `<dir>/.gitignore` с шаблоном `*.gen.ts`
- When выполняется сканирование
- Then `<dir>/**/*.gen.ts` исключается
- And файлы вне `<dir>` не исключаются этим правилом

Сценарий: отрицание
- Given `.gitignore` с `*.log` и `!keep.log`
- When выполняется сканирование
- Then `keep.log` включается, остальные `*.log` исключаются

### Требование: безусловные запреты

Встроенные запреты (`.git`, зависимости, сборки, `.env*`, ключи, lock-файлы; [src/security/policy.ts:8](src/security/policy.ts:8)) и шаблоны `.memoryignore` SHALL NOT отменяться отрицанием из `.gitignore`.

Сценарий: попытка открыть секрет
- Given `.gitignore` содержит `!.env`
- When выполняется сканирование
- Then `.env` не индексируется

### Требование: отключение

Учёт `.gitignore` SHALL отключаться настройкой. Отключённый учёт SHALL давать прежний состав индекса.

### Требование: исключённые каталоги не обходятся

Каталог, исключённый правилом, SHALL NOT обходиться рекурсивно.

### Требование: лимит размера

Лимит 512 KiB ([src/project/config.ts:18](src/project/config.ts:18)) SHALL сохраняться. Произвольный предел числа файлов SHALL NOT вводиться.

## Риски

- Состав индекса меняется: при последующем `sync` ранее включённые документы могут быть удалены. Перед выпуском нужно описать это в README и предусмотреть отключение.

## Не проверено

- Текущее поведение сканера для вложенных `.gitignore`: не читалось, сводки указывают только на чтение `.memoryignore` ([src/project/scan.ts:16](src/project/scan.ts:16); Sol: `scan.ts:15`).
- Объём каталогов, которые Git игнорирует, но сканер обходит: не измерялся.
