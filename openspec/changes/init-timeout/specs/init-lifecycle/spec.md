# init-lifecycle

Контракт `memory init` (CLI) и `memory sync` / `memory_sync` (MCP) для фонового запуска.

## Требования

### Требование: init возвращает accepted без ожидания индексации

`memory init` SHALL возвращать статус `accepted` и идентификатор задачи после сохранения задачи в manifest и подтверждения запуска фонового процесса. `accepted` SHALL NOT означать готовность индекса.

Сценарий: фоновый worker заблокирован
- Given проект без индекса и worker, который не завершает работу
- When выполняется `memory init`
- Then команда возвращает `accepted` с идентификатором задачи
- And возврат не ждёт завершения worker

Сценарий: родитель завершается раньше worker
- Given задача `accepted`, worker запущен
- When процесс `memory init` завершается
- Then worker продолжает работу
- And состояние задачи обновляется worker-ом, а не родителем

Сценарий: ошибка запуска
- Given процесс worker не удалось запустить
- When выполняется `memory init`
- Then вызывающий получает ошибку запуска
- And задача не остаётся в состоянии `running`

### Требование: --wait ждёт результат структурного этапа

`memory init --wait` SHALL ждать завершения структурного этапа и возвращать итог задачи. `--wait` SHALL NOT запускать embedding.

Сценарий: синхронный сценарий
- Given скрипт, которому нужен готовый лексический индекс
- When выполняется `memory init --wait`
- Then команда возвращает результат только после состояния `completed` или `failed`

### Требование: параметры сохраняют прежнее поведение

- `--no-index` SHALL отключать первичную индексацию.
- `--no-start` SHALL сохранять прежнее поведение: не входит в условие запуска индексации.

### Требование: один писатель индекса

На проект SHALL допускаться одна активная операция записи индекса. Конкурирующая операция SHALL получать `busy` с идентификатором активной задачи.

Сценарий: повторный init
- Given активная задача инициализации `<id>`
- When выполняется повторный `memory init`
- Then команда присоединяется к задаче `<id>` и не запускает вторую
- And ответ содержит `<id>`

Сценарий: конкурирующий sync
- Given активная задача инициализации `<id>`
- When выполняется `memory sync`
- Then команда возвращает `busy` с `<id>`

### Требование: sync в фоне

`memory sync --background` и `memory_sync(background: true)` SHALL запускать embedding-фазу в фоновой задаче и возвращать `accepted`. Синхронный `memory sync` SHALL оставаться совместимым.

### Требование: MCP без первичного init

Система SHALL NOT добавлять MCP-инструмент первичной инициализации. Первичная инициализация выполняется через CLI.

## Не проверено

- Поведение, когда среда уничтожает всю группу процессов при выходе родителя.
- Точный внешний таймаут вызывающего клиента.
