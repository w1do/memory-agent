# resume

Возобновление структурного этапа после остановки.

## Требования

### Требование: возобновление не пропускает работу

После остановки структурного этапа повторный запуск SHALL продолжить работу без пропуска неиндексированных файлов.

Сценарий: остановка внутри пачки
- Given задача остановлена в середине пачки
- When выполняется повторный `memory init`
- Then файлы пачки, не записанные в manifest, обрабатываются
- And файлы, записанные успешно, не индексируются повторно без причины

Сценарий: ошибка файла
- Given файл `<path>` завершился ошибкой в прошлом запуске
- When выполняется повторный запуск
- Then `<path>` попадает в очередь
- And курсор `last_index_path` не продвигается за него

Сценарий: новый или изменённый путь перед курсором
- Given файл появился или изменился по пути меньше `last_index_path`
- When выполняется повторный запуск
- Then файл попадает в очередь

### Требование: идемпотентность повторов

Повторная обработка незавершённой записи SHALL быть идемпотентной: повторный запуск не создаёт дубликатов в манифесте и в хранилище.

### Требование: курсор показывает завершённую пачку

`last_index_path` SHALL обозначать последнюю завершённую пачку. Описание в README SHALL соответствовать этому (правка O1).

## Не проверено

- Точка обрыва в прошлом запуске: лог не найден, `last_path.indexing = null` в снимке статуса.
- Поведение при повреждённом manifest: не описано в сводках.
