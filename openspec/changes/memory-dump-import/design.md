# Дизайн: `memory dump` и `memory import`

Решение принято Sol (`SPEC: READY`). Источник: `/tmp/dump-import-sol-decision.md`. Код не читался; все пути и имена ниже — из решения, не из реализации.

## Решения

### 1. Модель: переносимый логический снимок

Дамп — логическое содержимое трёх хранилищ, а не их внутренние файлы. Импорт заменяет память проекта целиком и не вычисляет embeddings.

### 2. Состав дампа

- `index.db`: файлы, чанки с текстом, символы, imports/exports, связи, аннотации и нужные метаданные индекса.
- SQLite создаётся заново из разрешённых таблиц и полей согласованного снимка. В дамп не попадают задачи, ошибки, блокировки, WAL и свободные страницы старой БД.
- Qdrant: все векторы float32, идентификаторы точек, payload и параметры коллекции.
- Typesense: полные документы и схема коллекции. Экспорт предпочтительнее пересборки: результат не зависит от версии сборщика документов.
- `annotations.json`: согласованное представление аннотаций SQLite и `.memory/annotations.json` по действующему правилу newer-wins.
- Исходники отдельно не копируются: их индексированные фрагменты уже в чанках.

### 3. Формат `./memory/<name>/`

```text
manifest.json
index.db.zst
annotations.json.zst
qdrant/points.jsonl.zst
qdrant/vectors.f32le.zst
typesense/documents.jsonl.zst
typesense/schema.json
```

- `points.jsonl` связывает каждую точку с порядковым номером в массиве векторов. Порядок фиксирован.
- Манифест содержит:
  - `formatVersion=1`;
  - версии приложения, SQLite-схемы и алгоритма ID;
  - `sourceProjectId`, дату UTC, версии сервисов, параметры коллекций;
  - embedding fingerprint: модель, неизменяемую ревизию или идентификатор весов, dimensions, обработку входа, усечение, нормализацию и distance;
  - список артефактов дампа с SHA-256 и размерами до и после сжатия;
  - список индексированных файлов: относительный путь, SHA-256 и размер индексированной версии;
  - счётчики записей, контрольные суммы логического содержимого и параметры построения ID, включая ordinal одинаковых чанков.
- `dumpId` — SHA-256 канонического манифеста без самого `dumpId`. Контрольные суммы артефактов входят в расчёт.
- Zstd используется потоково. Высокий коэффициент сжатия векторов не обещается.
- Оценка размера: 32 000 × 1536 × 4 байта = 196,6 МБ ≈ 187,5 MiB только векторов. Тексты и metadata увеличат размер. Это расчёт, не измерение.
- `memory/` по умолчанию добавляется в `.gitignore`. Передача — архивом или артефактом. При хранении в Git — LFS для крупных файлов.
- `memory/` исключается из индексации независимо от Git. Иначе дамп начнёт индексировать сам себя.
- `<name>` — один компонент пути. Абсолютные пути, `..` и выход через symlink запрещены.

### 4. Создание согласованного снимка (dump)

- Общая блокировка всех изменений памяти, включая аннотации. Экспорт SQLite, Qdrant и Typesense относится к одному состоянию.
- Требования к источнику: нет незавершённых изменений и pending embeddings; множества `chunkId` в SQLite, Qdrant и Typesense совпадают.
- Недостающие или лишние точки и документы, несогласованные payload — отказ. Автоматического исправления и embedding нет.
- Fingerprint берётся из происхождения сохранённых векторов, а не из текущей конфигурации. Неизвестное или смешанное происхождение — отказ.
- Запись идёт во временный каталог. После проверок — атомарное переименование в `./memory/<name>/`. Существующий `<name>` не перезаписывается.

### 5. Импорт

- До изменения активной памяти проверяются: формат, поддерживаемые схемы, размеры, SHA-256, пути и внутренняя согласованность.
- Fingerprint дампа сравнивается с эффективной конфигурацией получателя, включая overrides окружения. Embeddings для проверки не вычисляются.
- Совпадают модель, ревизия, обработка входа и dims — импорт разрешён. Любое несовпадение или неизвестное значение — понятная ошибка с обеими конфигурациями.
- Одинаковые 1536 dims у разных моделей (например, Qwen и OpenAI) совместимостью не считаются.
- `global.env` автоматически не меняется.
- Получатель сохраняет собственный `projectId` либо получает новый по своему root. Исходный `projectId` остаётся provenance.
- Перепривязываются: `projects.root`, абсолютные `files.path`, `projectId` и зависимые ID во всех таблицах, документах и payload.
- `fileId`, `chunkId` и UUID точек пересчитываются по версионированному алгоритму с полной картой соответствий. Сами векторы переносятся без embedding.
- Локальные адреса сервисов, credentials и регистрация проекта берутся у получателя.
- SHA-256 доступных исходников сравнивается с индексированными хешами. Для совпавших файлов обновляется локальный mtime.
- Изменённые или отсутствующие файлы помечаются `stale`; дополнительные файлы — `unindexed`. Снимок сохраняется. Аннотации stale-файлов считаются неактуальными.
- `sync` автоматически не запускается. Последующий явный `sync` обновит расхождения и может вычислить embeddings изменённых чанков.
- Импорт собирает отдельное поколение SQLite, Qdrant, Typesense и аннотаций и проверяет его до публикации.
- Единственный атомарный указатель активного поколения переключает все компоненты вместе. Читатели закрепляют поколение, писатели используют общую блокировку.
- Старое поколение сохраняется для отката. Журнал операции позволяет после сбоя либо завершить переключение, либо убрать staging.
- Повторный импорт того же `dumpId` при неизменённом активном поколении — проверка без дублей. После локальных изменений он снова заменяет память снимком.

### 6. Гарантия «то же самое»

- Проверяются: SQLite integrity, связи, счётчики, полные множества ID, тексты, payload, аннотации и логические хеши после обратного отображения ID.
- Все векторы перечитываются: dimensions, конечность значений и соответствие экспортированным float32 с абсолютным допуском `1e-6`.
- Допуск учитывает нормализацию при загрузке Cosine-векторов в Qdrant. Побитовая идентичность внутреннего хранения не обещается.
- Гарантия относится к содержимому снимка с заменёнными локальными привязками. Содержимое рабочего дерева и идентичный порядок поисковой выдачи вне гарантии.

### 7. Исключения

- Не переносятся: `.env*`, `global.env`, ключи, credentials, локальные конфиги сервисов, кэши, Docker volumes, логи и история задач.
- Если запрещённые файлы уже представлены в индексе, dump отказывается. Одного исключения файлов из упаковки недостаточно.

## Отвергнутые варианты

| Вариант | Причина отказа |
|---|---|
| Копировать всю `.memory/` | Машинные привязки, служебные данные, нет глобального индекса и векторов |
| Экспорт только SQLite | Без векторов нужен embedding при импорте |
| Нативные snapshot-файлы Qdrant и Typesense | Зависимость от версии сервиса и внутреннего формата |
| Автоматический embedding при импорте | Противоречит цели переноса без пересчёта; стоимость и внешний API |
| Автоисправление несогласованного источника | Скрывает ошибку индекса; dump должен отказать |
| Считать одинаковые dims совместимыми | Разные модели дают несопоставимые векторы |
| Автоматически менять `global.env` | Конфигурация получателя принадлежит получателю |
| Исключить запрещённые файлы только при упаковке | Они остаются в индексе и в векторах |

## Открытые риски

- Размер дампа на реальном проекте не измерен (см. оценку в разделе 3).
- Блокировка всех записей между процессами: механизм не проверен.
- Атомарное переключение поколения на файловой системе получателя (в том числе WSL2): не проверено.
- Старое поколение занимает место до отката или очистки. Политика очистки не определена.
- Набор поддерживаемых версий сервисов и SQLite-схем, которые импорт принимает, не определён.
- Расхождения Cosine-нормализации сверх float32 ограничены допуском `1e-6`; фактическая величина не измерена.
