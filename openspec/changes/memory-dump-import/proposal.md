# Перенос памяти проекта: `memory dump <name>` и `memory import <name>`

Status: Draft, ожидает реализации
Code: не реализовано. Решение архитектора: `SPEC: READY` (источник: `/tmp/dump-import-sol-decision.md`).

## Проблема

Владелец проекта хочет передать память другому разработчику. Сейчас готовой команды для этого нет. Память состоит из трёх хранилищ: SQLite (`index.db`), Qdrant (векторы) и Typesense (документы). Простое копирование `.memory/` не подходит:

- в каталоге есть машинные привязки (абсолютные пути, `projectId`, локальные адреса сервисов);
- глобального индекса и векторов в нём нет, их нельзя восстановить копированием;
- без векторов получатель вынужден пересчитать embedding для всех чанков, что долго и требует внешнего API.

Пример: в текущем состоянии источника статус показывает 638 чанков, 324 точки Qdrant и 0 pending embeddings. Это несогласованный снимок (точек меньше чанков). Строгий dump обязан такой источник отклонить.

## Цель

- `memory dump <name>` создаёт переносимый логический снимок памяти проекта в `./memory/<name>/` внутри проекта.
- `memory import <name>` загружает снимок. После импорта у получателя те же индекс, чанки, векторы и аннотации, без пересчёта embedding.
- Импорт не меняет конфигурацию получателя (`global.env` не трогается) и не запускает `sync` автоматически.
- Снимок либо создаётся полностью и согласованно, либо не создаётся. Импорт либо публикует полностью проверенную память, либо оставляет прежнюю.

## Что не входит в объём

- Копирование всего `.memory/` целиком.
- Нативные snapshot-файлы Qdrant и Typesense.
- Экспорт только SQLite без векторов.
- Автоматический embedding при импорте или после него.
- Автоматическое исправление несогласованного источника (недостающие или лишние точки и документы).
- Перенос исходников проекта: их индексированные фрагменты уже входят в чанки.
- Перенос `.env*`, `global.env`, ключей, credentials, локальных конфигов сервисов, кэшей, Docker volumes, логов и истории задач.
- Синхронизация памяти между машинами в реальном времени и слияние двух разных памятей.
- Изменение алгоритма поиска и порядка выдачи.

## Предлагаемое решение

Подробности, отвергнутые варианты и риски — в `design.md`. Кратко:

1. Дамп: манифест `formatVersion=1`, `index.db.zst`, `annotations.json.zst`, векторы float32 в `qdrant/vectors.f32le.zst` с файлом соответствия точек, документы Typesense и схема коллекции.
2. Создание только из согласованного снимка под общей блокировкой; сначала во временный каталог, затем атомарное переименование.
3. Импорт сначала проверяет формат и хеши, затем сравнивает embedding fingerprint с эффективной конфигурацией получателя. При несовпадении — понятная ошибка без изменения памяти.
4. Получатель сохраняет свой `projectId` (или получает новый по своему root). Все пути, ID и ссылки перепривязываются по карте соответствий.
5. Импорт собирает отдельное поколение и публикует его одним атомарным переключением. Старое поколение сохраняется для отката.

## Критерии приёмки

- `memory dump <name>` создаёт каталог с полным набором артефактов из `design.md`, манифест проходит проверку контрольных сумм.
- `memory import <name>` при несовпадении модели, ревизии, обработки входа или размерности отказывает до изменения памяти, в ошибке видны обе конфигурации.
- Все векторы после импорта перечитываются и совпадают с экспортом с допуском `1e-6`; embedding не вычисляется.
- Файлы с несовпадающим SHA-256 или отсутствующие помечаются `stale`; лишние — `unindexed`.
- Запрещённые файлы не попадают в снимок; dump отказывается, если они уже представлены в индексе.
- Повторный импорт того же `dumpId` не создаёт дублей; сбой на любом этапе оставляет прежнюю память доступной.
- Тесты из `tasks.md` проходят (команды в `tasks.md`, сейчас не запускались).

## Риски

- Размер: оценка для 32 000 чанков × 1536 × float32 — около 196,6 МБ (≈187,5 MiB) только векторов; тексты и metadata увеличат размер. Реальный размер не измерен.
- Согласованный снимок требует блокировки всех записей, включая аннотации; механизм блокировки между процессами не проверен.
- Атомарное переключение поколения на файловой системе получателя не проверено.
- Старое поколение занимает место до отката или очистки.
- Нормализация Cosine-векторов в Qdrant может давать расхождения сверх float32; гарантия задана допуском `1e-6`, а не побитовым равенством.

## Не проверено

- Фактический размер дампа на реальном проекте.
- Поведение блокировки и переключения поколения на целевых ОС и в WSL2.
- Версии сервисов, при которых формат дампа остаётся совместимым: набор поддерживаемых версий не определён.
- Имена тестовых файлов и точная структура модулей: предлагаемые в `tasks.md`, не подтверждены кодом.
