# import

Загрузка дампа командой `memory import <name>` и перепривязка к локальному проекту.

## Требования

### Требование: импорт проверяет дамп до изменения памяти

`memory import <name>` SHALL проверить формат, поддерживаемые схемы, размеры, SHA-256, пути и внутреннюю согласованность до изменения активной памяти.

Сценарий: повреждённый артефакт
- Given SHA-256 артефакта не совпадает с манифестом
- When выполняется `memory import <name>`
- Then команда завершается ошибкой с именем артефакта
- And активная память не изменяется

Сценарий: неподдерживаемая версия формата
- Given `formatVersion` в манифесте не поддерживается
- When выполняется `memory import <name>`
- Then команда завершается понятной ошибкой с версиями
- And активная память не изменяется

### Требование: несовпадение модели или размерности — отказ

Импорт SHALL отказать, если embedding fingerprint дампа не совпадает с эффективной конфигурацией получателя, включая overrides окружения. Embeddings для проверки SHALL NOT вычисляться.

Сценарий: другая модель
- Given модель в дампе отличается от модели получателя
- When выполняется `memory import <name>`
- Then команда завершается ошибкой
- And ошибка показывает обе конфигурации: дампа и получателя
- And активная память не изменяется

Сценарий: другая размерность
- Given dimensions в дампе отличаются от dimensions получателя
- When выполняется `memory import <name>`
- Then команда завершается ошибкой с обеими размерностями

Сценарий: одинаковые dimensions у разных моделей
- Given dimensions совпадают, но модель или ревизия различаются
- When выполняется `memory import <name>`
- Then импорт отказывает
- And совпадение размерности не считается совместимостью

Сценарий: неизвестное значение fingerprint
- Given поле fingerprint дампа неизвестно получателю
- When выполняется `memory import <name>`
- Then импорт отказывает с понятной ошибкой
- And `global.env` не изменяется

### Требование: перепривязка root и projectId

Импорт SHALL сохранять `projectId` получателя либо выдавать новый по его root. Исходный `projectId` SHALL остаться как provenance. Пути, ID и ссылки SHALL быть перепривязаны во всех таблицах, документах и payload.

Сценарий: перепривязка путей
- Given в дампе `projects.root` и абсолютные `files.path` указывают на машину владельца
- When выполняется импорт у получателя
- Then `projects.root` и `files.path` соответствуют локальному root получателя

Сценарий: собственный projectId
- Given получатель уже имеет `projectId` для этого проекта
- When выполняется импорт
- Then используется `projectId` получателя
- And `sourceProjectId` из дампа сохраняется как provenance

Сценарий: новые ID по карте соответствий
- Given `fileId`, `chunkId` и UUID точек пересчитываются по версионированному алгоритму
- When выполняется импорт
- Then составляется полная карта соответствий старых и новых ID
- And векторы переносятся без вычисления embedding

### Требование: файлы с несовпадающим хешем помечаются stale

Импорт SHALL сравнить SHA-256 доступных исходников с индексированными хешами из дампа. Изменённые или отсутствующие файлы SHALL получить `stale`. Лишние файлы SHALL получить `unindexed`.

Сценарий: файл совпал
- Given SHA-256 локального файла равен индексированному хешу
- When выполняется импорт
- Then файл не помечается stale
- And локальный mtime обновляется

Сценарий: файл изменён
- Given SHA-256 локального файла отличается от индексированного
- When выполняется импорт
- Then файл помечается `stale`
- And аннотации этого файла считаются неактуальными

Сценарий: файл отсутствует
- Given файл из дампа отсутствует локально
- When выполняется импорт
- Then файл помечается `stale`
- And снимок сохраняется

Сценарий: лишний файл
- Given локальный файл не входит в дамп
- When выполняется импорт
- Then файл помечается `unindexed`

### Требование: sync не запускается автоматически

Импорт SHALL NOT запускать `sync`. Последующий явный `sync` SHALL обновить расхождения и MAY вычислить embeddings изменённых чанков.

Сценарий: завершение импорта
- Given импорт завершён успешно
- When проверяется состояние
- Then embedding не вычислялся
- And `sync` не выполнялся

### Требование: импорт публикуется одним переключением

Импорт SHALL собрать отдельное поколение SQLite, Qdrant, Typesense и аннотаций, проверить его и опубликовать единственным атомарным переключением указателя активного поколения. Читатели SHALL закреплять поколение; писатели SHALL использовать общую блокировку.

Сценарий: успешный импорт
- Given новое поколение прошло проверку
- When выполняется переключение
- Then все компоненты переходят на новое поколение одновременно

### Требование: идемпотентность и откат

Повторный импорт того же `dumpId` SHALL NOT создавать дубликаты. Сбой на любом этапе SHALL оставлять прежнее поколение доступным или завершать переключение по журналу.

Сценарий: повтор того же dumpId
- Given активное поколение соответствует `dumpId` и не менялось локально
- When выполняется `memory import <name>` повторно
- Then дубликатов в памяти нет
- And команда сообщает, что импорт уже применён

Сценарий: повтор после локальных изменений
- Given после импорта локально менялась память
- When выполняется `memory import <name>` с тем же `dumpId`
- Then память заменяется снимком

Сценарий: сбой до переключения
- Given сбой произошёл на этапе сборки нового поколения
- When выполняется восстановление
- Then активное поколение не изменено
- And staging удаляется

Сценарий: сбой во время переключения
- Given журнал операции содержит незавершённое переключение
- When выполняется восстановление
- Then переключение доводится до конца или откатывается по журналу
- And старое поколение сохраняется для отката

## Не проверено

- Механизм атомарного указателя на целевой файловой системе: не проверено.
- Формат журнала операции и правила его очистки: не определены.
- Поведение при нехватке места для второго поколения: не проверено.
