# Задачи: `memory dump` и `memory import`

Все пункты не выполнены: код не реализован. Отметка `[x]` ставится только после реализации и проверки по коду.

Порядок: M1 → M2 → M3 → M4 → M5. Команды проверки предложены по образцу `init-timeout` (`npm test -- <файл>`), имена тестовых файлов не подтверждены и уточняются при реализации.

## M1. Формат и манифест

- [ ] Схема `manifest.json` с `formatVersion=1`, версиями и параметрами коллекций.
- [ ] `dumpId` вычисляется как SHA-256 канонического манифеста без `dumpId`.
- [ ] Контрольные суммы артефактов и индексированных файлов записаны в манифест.
- [ ] Каноническая сериализация детерминирована: один и тот же вход даёт тот же `dumpId`.

Проверка: `npm test -- test/unit/dump-manifest.test.ts`

## M2. `memory dump <name>`

- [ ] Создаётся `./memory/<name>/` с полным набором артефактов из `design.md`.
- [ ] Запись во временный каталог, атомарное переименование после проверок.
- [ ] Отказ при несогласованном источнике (pending embeddings, расхождение `chunkId`, лишние или недостающие точки).
- [ ] Отказ, если `./memory/<name>/` уже существует.
- [ ] Отказ, если запрещённые файлы представлены в индексе.
- [ ] Запрещённые файлы не попадают в артефакты.
- [ ] `<name>` с `..`, абсолютным путём или выходом через symlink отклоняется.
- [ ] `memory/` исключается из индексации.
- [ ] Общая блокировка записей на время снимка (механизм не проверен).

Проверка: `npm test -- test/unit/memory-dump.test.ts`

## M3. `memory import <name>`: проверки до изменения памяти

- [ ] Проверка SHA-256 артефактов и размеров до изменения активной памяти.
- [ ] Неподдерживаемый `formatVersion` и версии схем отклоняются понятной ошибкой.
- [ ] Несовпадение модели, ревизии, обработки входа или dimensions отклоняется; ошибка показывает обе конфигурации.
- [ ] Одинаковые dimensions при разной модели не считаются совместимыми.
- [ ] Неизвестное значение fingerprint отклоняется.
- [ ] Embedding при импорте не вычисляется.
- [ ] `global.env` не изменяется.

Проверка: `npm test -- test/unit/memory-import-checks.test.ts`

## M4. `memory import <name>`: перепривязка и поколения

- [ ] `projectId` получателя сохраняется, либо выдаётся новый по его root; `sourceProjectId` сохраняется как provenance.
- [ ] `projects.root` и абсолютные `files.path` переписаны.
- [ ] `fileId`, `chunkId` и UUID точек пересчитаны по версионированному алгоритму; карта соответствий полная.
- [ ] Векторы перенесены без embedding.
- [ ] Совпавшие по SHA-256 файлы получают локальный mtime; несовпавшие и отсутствующие помечаются `stale`; лишние — `unindexed`.
- [ ] Аннотации stale-файлов помечаются неактуальными.
- [ ] `sync` не запускается автоматически.
- [ ] Новое поколение собирается отдельно и публикуется одним атомарным переключением.
- [ ] Старое поколение сохраняется для отката.
- [ ] Журнал операции позволяет довести переключение или убрать staging после сбоя.
- [ ] Повторный импорт того же `dumpId` не создаёт дубликатов; после локальных изменений заменяет память.

Проверка: `npm test -- test/unit/memory-import-generation.test.ts`

## M5. Гарантия «то же самое» и документация

- [ ] SQLite integrity, связи, счётчики и полные множества ID совпадают после обратного отображения ID.
- [ ] Тексты, payload и аннотации совпадают с дампом.
- [ ] Все векторы перечитаны: dimensions, конечность значений, отличие от экспорта не больше `1e-6`.
- [ ] Round-trip тест: dump → import на чистом проекте → сравнение с источником по логическим хешам.
- [ ] Документация команд и формата: `memory/` в `.gitignore`, передача архивом или LFS.

Проверка: `npm test -- test/unit/memory-roundtrip.test.ts`

Полный прогон: `npm test` (команда подтверждена в `init-timeout`; для этого изменения не запускалась).
