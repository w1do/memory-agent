# Память проекта (project-memory)

Цель навыка: экономить токены. Сначала спрашиваем память, потом читаем только нужные фрагменты файлов. После правок держим индекс актуальным инкрементально.

## Когда применять

- Нужно найти модуль, файл, функцию, класс, импорт или тест.
- Нужно понять, какие файлы связаны с задачей.
- Перед тем как читать файл целиком, чтобы не тратить токены.
- После создания, изменения, переименования или удаления файла.

## Порядок работы при поиске

1. Проверь состояние индекса: MCP-инструмент `memory_status` или команда `memory status`.
   - Если `is_stale` или число устаревших файлов больше нуля, сначала вызови `memory_sync`.
   - Если Qdrant или Typesense недоступны, сообщи пользователю, что поиск в degraded-режиме, и выполни `memory start`.
2. Найди нужное через `memory_get_context` (для задачи целиком) или `memory_search` (для точного запроса).
   - Задавай `limit` (по умолчанию не больше 10) и `token_budget` или `max_chars`.
   - Для узкой области используй `path_prefix`, например `src/auth`.
3. Для связей вызови `memory_related` с `path` и `depth` 1–2.
4. Читай файл через `memory_get_file` только с диапазоном `line_start` и `line_end`, а не целиком.
5. Сверяй результат с `indexed_at` и `content_hash`. Если файл менялся после индексации (`is_stale`), перечитай только его диапазон через `memory_get_file`.

Если MCP недоступен, используй CLI:

```bash
memory search "<запрос>" --limit 10 --max-chars 2000
memory search "<запрос>" --json
memory status
```

Полностью перечитывать проект не нужно. Читай файлы только тогда, когда без них нельзя внести правку.

## Правило инкрементальной переиндексации

После любого изменения файлов в проекте обязательно обновляй индекс по изменённым файлам.

- Изменил, добавил или переименовал конкретные файлы: вызови MCP-инструмент `memory_update` с полным списком путей относительно корня проекта.

```json
{
  "paths": ["src/auth/AuthService.ts", "src/auth/AuthController.ts"],
  "reason": "добавлен файл авторизации"
}
```

- Удалил файл: тоже передай его путь в `memory_update`. Инструмент удалит chunks из Typesense и Qdrant. Если файл уже удалён, он будет обработан так же, как удалённый.
- Изменений много или не уверен, что все пути учтены: вызови `memory_sync` (CLI: `memory sync`). Он обрабатывает только новые, изменённые, переименованные и удалённые файлы.
- Команду `memory reindex` не используй для обычных правок. Она пересобирает весь индекс и тратит embeddings на весь проект. Запускай её только если пользователь явно попросил полный пересбор или индекс повреждён.

Порядок после правки:

1. Внеси изменения в код.
2. Вызови `memory_update` с путями всех созданных, изменённых и удалённых файлов или `memory_sync`.
3. Проверь ответ: поля `errors` и новые хеши. Если ошибка, сообщи о ней пользователю.
4. Подтверди актуальность через `memory_status` (число устаревших файлов должно быть 0).

Не выполняй `memory_update` для файлов вне проекта: инструмент отклонит такие пути, это защита от path traversal.

## Команды memory (CLI)

Запускай из корня проекта. Все команды описаны в README, раздел «Команды».

```bash
memory status [--json]                         # состояние индекса и сервисов
memory doctor                                  # диагностика Docker, Qdrant, Typesense, embeddings
memory search "<запрос>" --limit 10 --max-chars 2000 [--mode hybrid|lexical|semantic] [--language <lang>] [--json]
memory sync                                    # инкрементальная синхронизация (новые, изменённые, переименованные, удалённые)
memory reindex <путь1> <путь2>                 # переиндексация только указанных файлов
memory reindex                                 # полная пересборка: только по явной просьбе пользователя
memory start | memory stop                     # запуск и остановка Qdrant и Typesense
```

Для точечных правок передавай пути файлов относительно корня проекта в `memory reindex <пути>` или MCP `memory_update`. Директории не раскрываются в файлы, перечисляй их явно.

## Ограничения

- Не добавляй в индекс секреты: `.env`, ключи, сертификаты. Если путь попал в индекс, сообщи пользователю и проверь `.memoryignore`.
- Не возвращай пользователю большие куски памяти без запроса. Показывай пути, диапазоны строк и короткие фрагменты.
- Не меняй файлы проекта через память: MCP-сервер работает только для чтения исходников и обновления индекса.
- Не используй `memory_search` как замену проверке кода перед правкой: после правки всегда выполняй шаги обновления индекса.

## Пример: добавлен новый файл в модуль авторизации

1. Создан `src/auth/TokenService.ts`.
2. Вызвать `memory_update` с `paths: ["src/auth/TokenService.ts"]`.
3. Если файл изменил импорты в `src/auth/AuthService.ts`, добавить и его в `paths`.
4. Проверить `memory_search` по имени `TokenService` и `memory_related` для `src/auth/TokenService.ts`.

## Пример: файл удалён

1. Удалён `src/auth/LegacyAuth.ts`.
2. Вызвать `memory_update` с `paths: ["src/auth/LegacyAuth.ts"]`.
3. Проверить `memory_search` по имени `LegacyAuth`: результатов быть не должно.
